# マタマッチ（MataMatch）

**予定日が近い妊婦さんと、話せる相手が見つかる** — 妊婦さん同士のママ友づくりに特化したマッチングアプリのプロトタイプです。

恋愛・出会い系ではありません。「同じ時期に、近い場所で、似た状況にいる人」と悩みを分け合える相手を見つけることだけを目的にしています。

---

## セットアップ

```bash
npm install
npm run setup     # prisma generate → DB作成 → デモデータ投入
npm run dev       # http://localhost:3000
```

`npm run setup` を実行すると SQLite の `prisma/dev.db` が作られ、架空の妊婦さん 22 名分のプロフィールと、いいね・マッチ・トークのサンプルが入ります。

トップページ →「登録済みの方はログイン」→ デモアカウント一覧から **みかん** を選ぶのが一番わかりやすい入口です（いいねが 3 件届いていて、トークも 1 件進んでいます）。

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 開発サーバー起動 |
| `npm run build` / `npm start` | 本番ビルド / 起動 |
| `npm run typecheck` | 型チェック |
| `npm run db:reset` | DB を作り直してデモデータを再投入 |
| `npm run db:seed` | デモデータのみ再投入 |

## 技術構成

- **Next.js 16（App Router）+ TypeScript** — 画面はすべて Server Component、更新処理は Server Actions
- **Prisma + SQLite** — 追加のミドルウェア不要、リポジトリを clone すればそのまま動く
- **CSS のみ**（`src/app/globals.css`） — UI ライブラリなし。デザイントークンを CSS 変数で定義し、ダークモードにも対応

```
src/
  app/
    page.tsx                 トップ（サービス紹介）
    signup/                  プロフィール登録
    login/                   ログイン・デモアカウント選択
    discover/                おすすめ一覧＋絞り込み
    users/[id]/              プロフィール詳細・いいね・通報
    likes/                   もらった／送ったいいね
    matches/                 トーク一覧
    matches/[id]/            1対1トーク
    mypage/                  プロフィール編集・ブロック管理・退会
    safety/                  安全に使うためのガイドライン
  components/                アバター、相性リング、タグ、カードなど
  lib/
    matching.ts              相性スコアの算出（下記）
    pregnancy.ts             妊娠週数の計算
    queries.ts               一覧取得（除外条件をここに集約）
    actions.ts               Server Actions（いいね・トーク・通報など）
    validation.ts            入力チェック
prisma/
  schema.prisma              データモデル
  seed.ts                    デモデータ
```

## 相性スコアの考え方

`src/lib/matching.ts` で 5 つの観点を重み付けし、0〜100 点にまとめています。重みは `MATCH_WEIGHTS` を書き換えれば調整できます。

| 観点 | 配点 | 理由 |
| --- | --- | --- |
| 妊娠週数の近さ | 32 | 悩みの内容は週数でほぼ決まる。1週差なら満点、13週以上離れるとほぼ0 |
| エリアの近さ | 26 | 産院・自治体サービス・保活の話が通じる（同市区町村 > 同都道府県 > 同地方） |
| 共通の関心タグ | 24 | 会話のきっかけ。共通3個で満点に近づく |
| 初産／経産の一致 | 10 | 経験値が揃うと相談しやすい |
| 年代の近さ | 8 | 補助的 |

一覧では点数だけでなく「週数が1週差」「同じ世田谷区」「共通のタグ3個」といった**根拠のバッジ**を出しています。スコアだけ見せられても納得しづらいためです。

## プライバシーと安全性の設計

このジャンルは扱う情報が繊細なので、最初から以下を前提にしています。

- **本名・住所・電話番号・医療記録は一切保持しない。** 顔写真のアップロードもなく、アバターはニックネームの頭文字から自動生成
- **居住地は「都道府県＋市区町村」まで。** 番地は入力させない
- **出産予定日は本人にしか見せない。** 他ユーザーに見えるのは妊娠週数と「2026年11月ごろ」という粒度の予定月だけ
- **相互いいねが成立するまでトークは始まらない。** 一方的にメッセージは送れない
- **通報・ブロックを全プロフィール／全トークに常設。** ブロックすると双方の一覧から消え、いいねとマッチとトークも同時に解除される（`applyBlock`）
- **医療の免責を導線上に置く。** 登録画面・トップ・トーク画面・ガイドラインの 4 箇所で「医療的な判断は主治医へ」と明示

`/safety` に、勧誘（妊婦コミュニティで実際に起きるマルチ商法など）、断定的な医療アドバイス、実際に会うときの注意をまとめたガイドラインを置いています。

## プロトタイプとして割り切っている点

本番運用の前に、少なくとも以下が必要です。

1. **認証** — 現在は Cookie にユーザー ID を入れるだけで、パスワードもトークン署名もありません（`src/lib/session.ts`）。メールリンク認証や OAuth への差し替えが必須です
2. **妊婦であることの確認** — なりすまし対策が未実装です。母子手帳の一部提示や、産院連携などの検討が必要です
3. **通報の運用** — `Report` テーブルに保存するだけで、管理画面と対応フローがありません
4. **リアルタイム性** — トークはページ遷移で更新されます。WebSocket / Server-Sent Events による購読は未実装です
5. **DB** — SQLite なので単一プロセス前提です。PostgreSQL への切り替えは `prisma/schema.prisma` の `provider` 変更が起点になります
6. **画像・メディア** — 意図的に持っていません。エコー写真などの共有を許すなら、保存範囲と削除要件を先に決める必要があります

## デモデータについて

`prisma/seed.ts` のプロフィールはすべて**架空**です。出産予定日は「実行日からの相対日数」で生成されるため、いつセットアップしても週数がほどよくばらけます。
