# App Store 公開と収益化までのロードマップ

競合リサーチの結論（[competitive-research.md](./competitive-research.md)）を踏まえた、現状のプロトタイプから「App Store で公開して収益を上げる」までの道筋。

---

## 0. 先に、いちばん大事な話：収益モデルの前提が恋愛系とは違う

| | 恋愛マッチング | ママ友／妊婦向け |
|---|---|---|
| 月額 | 男性 3,700〜4,160円（Pairs 3,700円、with 4,160円、Omiai 3,900円） | **350〜400円**（MAMATALK 350円、ママリプレミアム 400円） |
| 課金構造 | 女性無料・男性課金の非対称モデルが成立 | **全員女性。「片側が払う」構造が使えない** |
| 在籍期間 | 数か月〜数年 | **妊娠期のみなら最長10か月** |

**サブスク単体で成立させるのは、かなり厳しい。** 仮に月480円・課金率5%とすると、1万MAUで月24万円。広告費を回すには足りない。

したがって収益の柱は次の優先順で考えるべき。

### 収益化の優先順位（推奨）

1. **B2B2C：自治体・産院・企業への提供 ← 最有望**
   産後うつ・孤立の予防は自治体の母子保健事業として予算が付く領域。「産婦人科オンライン」等が自治体・企業導入モデルで先行している。1契約が個人課金の数百人分になり、営業先が明確。**妊婦の孤立を減らすというプロダクトの目的とも利害が一致する**（広告と違って、ユーザーの不安を煽らずに稼げる）。
2. **専門家相談の手数料**
   通話インフラをすでに持っているので、助産師・産後ドゥーラとの1対1有料相談へ横展開できる。相場は30分2,500円前後。
   なお **App Store Guideline 3.1.1 は「real-time person-to-person services（家庭教師、医療相談など）」を IAP の例外**としており、この形なら Apple 手数料を回避できる可能性がある（要事前確認）。ただし自治体・病院の無料相談枠が competing free option として存在する点は織り込む必要がある。
3. **フリーミアム（月480円想定）**
   有料化しても体験が損なわれない範囲に絞る：検索条件の拡張、いいね無制限、既読表示、通話時間の上限解放、プロフィールの非表示。**「いいねを見るのに課金」のような不安につけ込む設計は避ける**（このユーザー層では信頼を失うほうが高くつく）。
4. **タイアップ・コマース**
   出産準備品は購買が一点集中する。ただし妊婦向けの広告は慎重に。医療的判断に影響しうる商材（サプリ、民間療法）は最初から扱わない方針を明文化しておく。
5. **匿名集計データ**（Peanutが実施）は日本では要配慮個人情報に近く、扱うなら別途の同意設計が要る。**当面は手を出さない**のが安全。

### 在籍10か月問題への対処

妊娠期だけでは LTV が積み上がらない。**「妊娠期に獲得 → 産後・育児期にそのまま継続」の導線を最初から入れる。** 具体的には、出産予定日を過ぎたら自動でモードを切り替え（週数 → 月齢）、同じ相手との関係を維持したまま育児期のマッチングに接続する。既存のママ友アプリが育児期中心なのは、そこに滞在時間があるから。妊娠期は競合が薄い**参入のくさび**として使い、育児期で回収する。

## 1. フェーズ計画

### Phase 0 — 現在地（完了）
Next.js の Web プロトタイプ。プロフィール、相性マッチング、いいね／相互マッチ、トーク、**アプリ内音声通話（WebRTC）**、通報・ブロック、退会。

### Phase 1 — 本番に耐えるバックエンド（1〜2か月）

| 項目 | 現状 | やること |
|---|---|---|
| 認証 | Cookie にユーザーIDを入れるだけ | メールリンク or SMS 認証。セッションは署名付きトークン |
| DB | SQLite | PostgreSQL（Supabase / Neon / RDS） |
| 妊婦確認 | なし | **最重要。** 母子健康手帳の一部提示 or 産院連携。完全自動は難しいので目視審査＋バッジ表示が現実的 |
| コンテンツフィルタ | なし | **Guideline 1.2 の必須要件。** 勧誘ワード・URL・連絡先の自動検出＋要確認キューへ |
| 通報運用 | DBに保存するだけ | 管理画面、対応SLA、公開の問い合わせ窓口（1.2 の「published contact information」） |
| 時刻 | 通話受付時間のみ JST 固定済み | 妊娠週数の計算も含めて全体を Asia/Tokyo 基準に統一 |

### Phase 2 — ネイティブアプリ化（2〜3か月）

**Capacitor で Web を包むだけは避ける。** Guideline 4.2 は「Webサイトの再パッケージ」を明確に拒否対象としている。加えて、以下はネイティブでないと成立しない。

- **着信通知**：現在のポーリングはアプリを閉じたら動かない。**APNs の VoIP push ＋ CallKit**（iOS）／FCM ＋ ConnectionService（Android）が必要。
- **バックグラウンド音声**：画面ロック中の通話継続。
- マイク権限、電話帳との衝突回避、通話中の他アプリ挙動。

**推奨構成：Expo（React Native）＋ 既存の Next.js を API サーバーとして残す。**

WebRTC の実装は2択。

| | 自前（react-native-webrtc + coturn） | マネージド（LiveKit / Twilio / Agora） |
|---|---|---|
| コスト | サーバー代のみ。安い | 従量課金（分あたり） |
| 手間 | TURN の運用、NAT越えのデバッグ | ほぼ不要 |
| 判断 | 通話が主機能でなく1対1のみなら現実的 | **最初はこちら推奨。** 通話品質の問題で離脱されるのが一番痛い |

いずれにせよ **TURN サーバーは必須**。現在のコードは STUN のみで、携帯回線や対称NAT 環境ではつながらない（`NEXT_PUBLIC_STUN_URLS` で差し替えられるようにはしてある）。

### Phase 3 — 審査を通す（2〜4週間）

App Store 提出前チェックリスト:

- [ ] **1.2 UGC**：フィルタ／通報／ブロック／公開連絡先の4点。通報には "timely responses"（時間の明示はないが、24時間以内の運用を目安にすると安全）
- [ ] **5.1.1(v)**：アプリ内でのアカウント削除 — *実装済み*
- [ ] **4.2**：Webの焼き直しに見えないこと（ネイティブ通話・プッシュ・オフライン表示があれば十分）
- [ ] **3.1.1**：サブスクは IAP 経由。専門家相談は person-to-person 例外を事前照会
- [ ] **年齢レーティング**：UGC を含むソーシャルは 17+ を求められることが多い。12+ で通す例（Instagram等）もあるが、審査で指摘されたら 17+ に落とす前提で
- [ ] プライバシーラベル（App Privacy）。**妊娠・出産予定日は健康関連情報**として申告が要る
- [ ] 医療的な助言をしないことを、アプリ内とストア説明文の両方に明記（誤って医療アプリと判定されるのを避ける）
- [ ] 利用規約・プライバシーポリシー・特定商取引法に基づく表記
- [ ] **HealthKit は当面使わない**（5.1.2(vi) によりデータのマーケティング利用が禁止され、扱いが重くなる）

### Phase 4 — グロースと収益化（公開後）

1. 最初の100人は**エリアを絞って**集める。マッチングは密度が命で、全国に薄く1,000人いるより1つの区に100人いるほうが機能する。世田谷区・武蔵小杉のような子育て世帯の集積地から。
2. 自治体・産院への営業を並行（Phase 1 と同時に着手してよい。導入検討は時間がかかる）。
3. サブスクは**ユーザーが1万人を超えてから**。それ以前は課金より継続率を見る。
4. 見るべき指標：**マッチ成立率 > DL数**。MAMATALK が10万DLで13万マッチという水準が比較対象になる。

## 2. いま塞ぐべきリスク（優先順）

| リスク | 影響 | 対処 |
|---|---|---|
| **なりすまし**（妊婦でない人物の侵入） | サービスの根幹が崩れる。事故が1件起きたら終わる | Phase 1 で妊婦確認を入れる。それまでクローズドβに留める |
| **勧誘・マルチ商法** | 実際にこの層で発生している | 自動フィルタ＋通報運用。「通話でのトラブル」の通報導線は実装済み |
| **音声のモデレーション不能性** | 証拠が残らず、通報しても判断できない | 現状は相互マッチ後のみ・呼び出し2段階・受付時間・通話記録の可視化で面を絞っている。将来は「通報時のみ直近数分を暗号化保存」等を、事前同意のうえで検討 |
| **在籍10か月** | LTV が積み上がらない | 産後モードへの自動移行を Phase 1〜2 で設計に入れる |
| **TAM 縮小**（出生数10年連続減） | 市場が毎年縮む | 単価の高い B2B2C へ寄せる。個人課金だけで戦わない |
| **異性交際目的の混入** | 出会い系サイト規制法の適用対象になりうる | 女性限定を維持し、規約で明示。本人確認と合わせて担保 |

## 3. 直近でやるなら、この順

1. **妊婦確認の方式を決める**（これが決まらないと本番公開できない）
2. 認証を差し替え、PostgreSQL へ移行
3. コンテンツフィルタ＋通報の管理画面
4. Expo でネイティブ化、通話は LiveKit などのマネージドに載せ替え
5. 1エリア限定のクローズドβ（目標：そのエリアで100人・マッチ率30%）
6. 並行して自治体・産院に当たる
